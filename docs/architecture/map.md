# Map boundary (Phase 5 public UI)

The public React-Leaflet map uses `SITUATION` and `ROUTE` modes with separate flood-event, water-station, risk-area, and road-condition layers. Existing Phase 2 spatial GET routes accept `bbox=minLng,minLat,maxLng,maxLat`, return GeoJSON in WGS84, and paginate. The UI fetches only enabled layers for the visible map bounds after a short debounce, aborts superseded requests, and caps each collection at the first 100 records. A full page is visibly labeled as potentially truncated; zoom into a smaller extent rather than requesting the entire database. Geometries and safety-relevant provenance are checked at the API boundary before rendering. Point, multipolygon, and multiline geometries remain indexed by PostGIS GiST. No composite `/map/features` route is implemented.

The map displays OpenStreetMap standard tiles as an external basemap with attribution; tile availability does not affect the flood-data status. Coordinates remain `[longitude, latitude]` in GeoJSON and are converted to Leaflet `[latitude, longitude]` only at its rendering boundary. Markers, polygons, and lines can be selected on the map or from a keyboard-accessible text list. Selected evidence discloses source type/name, observed time or risk validity period, freshness, verification, and confidence where the API provides them. Station readings are requested only upon selection and retain their own source distinct from the station source. Unknown/stale road conditions are gray dashed lines with `UNKNOWN` text, never treated as passable. Legend entries follow visible layers. Loading, partial failure, full failure, empty, and truncated states are distinct.

`ROUTE` mode accepts manually entered WGS84 points or map clicks and labels those user-selected points, but draws no route line and calculates no path. Its panel lists road conditions and flood events in the current viewport only; it does not claim spatial intersection with a proposed route or recommend safe travel. A routing engine/API and intersection-aware route evaluation remain unimplemented. CCTV, safe areas, and administrative boundaries have no public map APIs and therefore no fabricated layer data. Separate layer components leave room for later clustering without an added dependency now.

Phase 6 adds a separate verified `COMMUNITY` report feed and an optional map layer. It never inherits `OFFICIAL` styling or changes route evaluation. The public endpoint excludes pending and rejected reports. See `community-reports.md` for review and publication policy.
