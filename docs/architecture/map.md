# Map boundary (Phase 5 public UI)

The public React-Leaflet map uses `SITUATION` and `ROUTE` modes with separate flood-event, water-station, risk-area, and road-condition layers. Existing Phase 2 spatial GET routes accept `bbox=minLng,minLat,maxLng,maxLat`, return GeoJSON in WGS84, and paginate. The UI fetches only enabled layers for the visible map bounds after a short debounce, aborts superseded requests, and caps each collection at the first 100 records. A full page is visibly labeled as potentially truncated; zoom into a smaller extent rather than requesting the entire database. Geometries and safety-relevant provenance are checked at the API boundary before rendering. Point, multipolygon, and multiline geometries remain indexed by PostGIS GiST. No composite `/map/features` route is implemented.

The map displays OpenStreetMap standard tiles as an external basemap with attribution; tile availability does not affect the flood-data status. Coordinates remain `[longitude, latitude]` in GeoJSON and are converted to Leaflet `[latitude, longitude]` only at its rendering boundary. Markers, polygons, and lines can be selected on the map or from a keyboard-accessible text list. Selected evidence discloses source type/name, observed time or risk validity period, freshness, verification, and confidence where the API provides them. Station readings are requested only upon selection and retain their own source distinct from the station source. Unknown/stale road conditions are gray dashed lines with `UNKNOWN` text, never treated as passable. Legend entries follow visible layers. Loading, partial failure, full failure, empty, and truncated states are distinct.

`ROUTE` mode accepts manually entered WGS84 points or map clicks and labels those user-selected points, but draws no route line and calculates no path. Its panel lists road conditions and flood events in the current viewport only; it does not claim spatial intersection with a proposed route or recommend safe travel. A routing engine/API and intersection-aware route evaluation remain unimplemented. CCTV, safe areas, and administrative boundaries have no public map APIs and therefore no fabricated layer data. Separate layer components leave room for later clustering without an added dependency now.

Phase 6 adds a separate verified `COMMUNITY` report feed and an optional map layer. It never inherits `OFFICIAL` styling or changes route evaluation. The public endpoint excludes pending and rejected reports. See `community-reports.md` for review and publication policy.

## Shared location and report-map navigation (2026-10-04)

The full situation map and report location picker share an in-memory camera snapshot and a timestamped user position through `shared/map`. Client-side navigation restores the last center and zoom; report editing centers its existing incident pin instead, and explicit risk/bounds deep links take priority on the situation map. Overview and risk previews do not write the shared camera. Reloading the app clears this memory; neither GPS coordinates nor camera history are persisted to browser storage.

Both maps use the same zoom range (8–18), metric scale, SVG locate control, and non-animated recentering. At the Ongkharak reference latitude the closest view shows a real 50 m scale; this is not an incident/search radius or a claim of GPS precision. The locate action reuses a valid fix younger than 60 seconds, otherwise requests a bounded browser fix without forcing high accuracy. There is no permission request on mount or continuous tracking. The button is highlighted only while the user point is within 12 screen pixels of the map center. Panning away changes both its pressed state and accessible description, not just its color. Failed, stale, canceled, reset and unmounted location requests cannot move the camera or incident pin.

Report-map expansion retains the same Leaflet instance and draft, supports Escape and contained keyboard traversal, restores focus, and keeps the selected incident independent of the blue GPS point. Resize invalidation preserves the geographic center. Expanded maps sit above floating shell widgets; metric scales remain clear of attribution and the situation legend. A separate report action always requests a fresh high-accuracy fix before explicitly selecting it as the incident. Verified-only public report APIs and `report.verified` refreshes remain unchanged.

Viewport layer requests remain debounced and cancel superseded bounds, but publish each completed layer independently. During refresh, retained results are visibly labeled as previous, with failure/truncation metadata preserved until that layer settles. Hidden layers are removed immediately; a failed current layer does not retain its old evidence. Lists and risk cards can show completed layers while others are still pending. GPS/camera movement never waits for these requests, and retained evidence is not reclassified as current or safe.

## Map-first interaction (2026-10-03)

The full `/map` page now prioritizes the map canvas, with floating layer toggles, situation/route switching, zoom/reset/fit controls, an expandable map view, and a synchronized legend. The keyboard-accessible feature list is available through the visible list button rather than a permanently open sidebar. On phones the layer menu starts collapsed, and requested details use a scrollable bottom sheet above the application navigation. Full-map expansion supports Escape and contained keyboard traversal.

Clicking a marker or a risk/road geometry opens a Leaflet popup at the selected position. Point markers also accept Enter and Space. Popups disclose the actual source, effective status, freshness and observation/validity timestamps; selecting a water station requests its latest reading and keeps reading provenance separate from station provenance. A water reading is never a safety classification. The details button opens the full evidence panel; Escape or the close button dismisses the popup with focus restoration. Hiding its layer or changing modes clears the popup. Popup auto-pan can revalidate viewport data; layout changes in loading/error messages do not resize the normal map and cause request loops.

Search is intentionally limited to stations and risk areas in the successfully loaded viewport collections; it is not a geographic place-search service and remains subject to each layer's 100-record limit. A result focuses its real geometry and opens the popup, without opening the details panel automatically. Risk-directory cards link to `/map?risk=<id>&bbox=<WGS84 bounds>` when valid geometry is available. Bounds from the URL are validated before changing the camera, and the selected area's popup is populated only from the map API response. Missing/truncated/unavailable selected areas are reported explicitly, not fabricated.

No dependencies, map APIs, thresholds, route calculations, administrative boundaries, or synthetic live observations were added. Overview and risk-preview maps keep their existing direct-detail selection behavior.
