# Flood Watch Ongkharak — Visual Direction

Reference images under:
docs/design/references/

The public redesign targets the visible composition of `01-overview.png`, `02-alerts.png`, `03-risk.png`, `04-map.png`, and `06-reports.png`. `05-cctv.png` is excluded; no camera navigation, fake stream, or camera layer is part of this redesign.

Use the separately supplied institutional utility-header and centered login references for those surfaces. Brand the login as Flood Watch, not the sample LostLink product. TH/EN and Google authentication remain visibly unavailable until implemented; password recovery has an informational UI but sends no request. Do not prefill example credentials.

Self-host Inter Variable for Latin text and numerals and Noto Sans Thai Variable for Thai. Use original code-native artwork only as illustration; it must not imply a live flood observation. Verified event photos and metrics must come from the API, never from the reference mockups.

## Style

- Apple / Cupertino-inspired web interface
- Soft Blue atmosphere
- Clean, calm and professional
- Spacious layout
- Subtle depth
- Selective Liquid Glass
- High information clarity

## Background

Primary background gradient:

#F8FBFF
→ #EAF3FF
→ #DCEBFF

Use subtle radial blue highlights where appropriate.

## Primary

#3B82F6

## Semantic colors

Danger:  #EF4444
Warning: #F59E0B
Success: #10B981
Info:    #0EA5E9

## Typography

Use clean modern sans-serif typography.

Prioritize:
- readable Thai text
- clear hierarchy
- generous whitespace

## Glass

Use glass selectively for:

- Sidebar
- Navigation
- Floating controls
- Search
- Map toolbar
- Bottom sheets
- Overlays

Do NOT make every data card glass.

Main data cards should normally use high-readability white surfaces.

## Desktop

Use:
- left sidebar
- spacious main content
- responsive card grid
- clear page heading
- floating/compact utility controls

## Mobile

Desktop sidebar becomes iOS-style bottom navigation.

Respect safe areas and touch targets.

## Data UI

Every situation card should be capable of showing:

- status
- source
- provenance
- freshness
- observation time

Do not rely on color alone.

## Important

OFFICIAL / COMMUNITY / AI must look visually distinguishable.

UNKNOWN must not visually imply SAFE.

Never fabricate data just to make the design look populated.
